# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Internal Streamlit web app for Light Human (Vietnamese recruitment agency): upload a candidate CV (PDF/image/DOCX) → an on-server extractor builds the profile JSON → staff review/edit → export a branded "Hồ sơ ứng viên" PDF with the candidate's contact details removed. **No external AI/API is called** (OpenAI was removed 11/2026; CV data must not leave the server). **`docs/SKILL.md` is the business spec for the PDF** (layout, what to strip, naming `LH - CV <Vị trí> - <Họ tên> - <ddmmyyyy>.pdf`, checklist); the template and checks implement it. `docs/prompts/system_prompt.txt` (the last OpenAI prompt, archived) is the detailed extraction spec for the rule-based extractor. `docs/de_xuat_bo_openai.md` is the plan for replacing OpenAI (phase B: rule-based PDF parser + manual fallback).

The user communicates in Vietnamese. Identifiers are English (PEP 8: functions, variables, classes, internal dict/session keys, `config/company.toml` keys, file names); user-facing strings, PDF text and comments/docstrings stay Vietnamese. Every function/class has a one-line Vietnamese `#` comment above it — keep that convention for new code.

## Repo layout

- Repo root: `README.md`, `CLAUDE.md`, `.gitignore`, `.vscode/`, `docker-compose.yml` (builds `./system`, mounts root `data/`; the app only `expose`s 8501, the `nginx` service publishes port 80 with basic auth), `nginx/conf.d/fillcv.conf` (reverse proxy: WebSocket `/_stcore/stream`, `client_max_body_size` ↔ `MAX_UPLOAD_MB`; `nginx/.htpasswd` is gitignored), `.github/` (CI workflow + dependabot), `docs/` (incl. `SKILL.md`), `data/` (never committed).
- `system/`: all source code plus `Dockerfile`, `.dockerignore`, `requirements*.txt`, `.coveragerc`, `.streamlit/`, `tests/`. It is the Docker build context and the working directory for every Python command and CI job. Paths below (`infra/…`, `services/…`, `config/…`, `tests/…`) are relative to `system/`; `docs/…` is relative to the repo root.

## Commands

```powershell
cd system                                         # every command below runs from system/
python -m pip install -r requirements-dev.txt     # app deps (pinned) + pytest/coverage/python-docx
python -m playwright install chromium             # required: PDFs are rendered by Chromium
python -m streamlit run app.py                    # http://localhost:8501 — no .env needed

python -m pytest -q                               # full suite (~260 tests, incl. real Chromium renders)
python -m pytest -q -m "not slow"                 # skip Chromium integration tests
python -m pytest -q tests/test_extraction.py tests/test_rules.py   # extractor interface + rule-based parser
python -m services.extraction.rules.measure cv.pdf [--expect answer.json]   # parser metrics, prints numbers only
python -m infra.tokens                            # print token tables to paste into docs/design-system.md
```

Run everything from `system/` (`PROJECT_ROOT` in `infra/settings.py`): the folders are implicit namespace packages (no `__init__.py`), imports are written without a `system.` prefix, and `render_worker` is launched with `-m` and `cwd=PROJECT_ROOT`. CI (`.github/workflows/ci-cd-web-app.yml`) runs `ruff check .`; there is no ruff config file. On Windows, set `PYTHONIOENCODING=utf-8` when a script prints Vietnamese, or the console raises `UnicodeEncodeError`.

Configuration: every value has a default in `infra/settings.py` (or `config/company.toml`) and can be overridden only by **OS environment variables** (`CV_EXTRACTOR`, `EXTRACT_MAX_CONCURRENT`, `EXTRACT_QUEUE_TIMEOUT`, `MAX_UPLOAD_MB`, `MAX_CV_PAGES`, `OUTPUT_DIR`, `LOG_DIR`, `OUTPUT_RETENTION_DAYS`, `RENDER_*`, `COMPANY_CONFIG`, `LOGO_PATH`, `LOGO_HEADER_PATH`, `CHROMIUM_NO_SANDBOX`). There is no `.env` / `python-dotenv`.

## Architecture

Layered monolith, one Python process; dependencies only point downward:

- `app.py` (+ `ui/`) — Streamlit orchestration and `session_state` only. `ui/components.py` returns HTML strings (pure functions), `ui/profile_form.py` is the edit form (one `_edit_*` function per section type, dispatched via `EDITORS_BY_TYPE`), CSS lives in `ui/styles.css`.
- `core/pipeline.py` — business flow: `read_cv()` (check file → extractor → schema validation → portrait), `make_pdf()` (render + checklist), `save_copy()` (PDF + a `.json` with the same stem: `export_json()` = `{format, exported_at, extractor, project, position, cv}`, the CV exactly as rendered, kept in `ss.pdf_cv`; retention deletes both), `stage_labels()`. `core/pdf_status.py` — `compute_status()`, the rule that enables the "Tải PDF" button and the status pill.
- `services/extraction/` — `base.py` is the extractor interface (`Extractor` Protocol, `SourceDoc`, `ExtractionResult`, `ExtractionError`, `get_extractor()` chosen by `CV_EXTRACTOR`, `check_file`, `validate`, `extractor_version`, `review_messages`); `rules/` is the default backend (`CV_EXTRACTOR=rules`, PDF with a text layer only, no OCR) and `manual.py` the fallback (probes the file, returns a blank schema-valid skeleton, everything flagged for review; `rules` returns it with a reason for DOCX/images/scans/garbled fonts/no headings). `services/ai/models.py` is the Pydantic schema (folder name kept from the AI era). `services/pdf` (`render.py`, `template.html` + `template.css`, `render_worker.py`, `pdf_utils.py`), `services/privacy/checks.py` (PII detection + PDF checklist).
- `infra/` — `settings.py` (defaults + env overrides, `config/company.toml` loader, supported extensions, `MAX_UPLOAD_MB`, `extractor_name()`), `tokens.py` (design tokens), `logging_setup.py`, `storage.py`.

Things that span several files and are easy to break:

- **Call collaborators through the module, not imported names.** `core/` does `from services.pdf import render` / `from services.extraction import base as extraction` then `render.build_pdf(...)`, `extraction.get_extractor()`. Tests (incl. Streamlit `AppTest`) monkeypatch `base.get_extractor` (fixture `stub_extractor` in `tests/conftest.py`), `render.build_pdf`, `checks.scan_pdf`, `render.extract_photo`; `from x import fn` would silently bypass the fakes.
- **Extractor contract**: an extractor returns `ExtractionResult(cv, warnings, confidence, stages, backend)`. `cv` must match the schema exactly — `CVData` forbids extra fields, so **confidence/warnings never go into the JSON**; they travel in the result, are stored in `ss.review = {"confidence": {path: score}, "notes": [(path, msg)]}` and the form shows "Cần xem" badges (`REVIEW_THRESHOLD` 0.7; paths like `sections[2].jobs[0].period`). `read_cv` always re-validates with `CVData`. Each extractor declares `stages`; it must call `progress(stage.key)` when a stage starts (use `base.stage_run`) — the waiting screen shows only real stages (`pipeline.stage_labels()` = extractor stages + photo + PDF). Warning messages are rendered as markdown and logged nowhere — write them in code, never copy CV text into them. Register new backends in `base.BACKENDS`.
- **Rule-based parser** (`services/extraction/rules/`), one module per stage, each reported as a real stage: `pdf_text.read_lines` (PyMuPDF spans → `Line` with size/bold/italic/bullet, 2-column gutter detection, same-row merge within a column, running header/footer removal, `TextQualityError` for scans/garbled text) → `sections.split_sections` (heading = keyword match, or same style as matched headings; words that are also in-job labels like "Thành tích"/"Dự án" only count as headings with heading style) → `personal` (name = largest font on page 1; label-based removal of contacts/address/hometown/marital/nationality/ID on **every** line; DOB → year; salary → `expected_salary`; original stats row) → `content.build_section` (wrapped-line joining uses the page column's right edge; jobs anchored on date ranges with look-back/look-ahead for company/role; sub-roles = indented dated lines; grid layouts split into cells) → `analysis` (generated stats floor years and are only created from real data; recruiting flags; language). **All keywords live in `config/extraction_rules.toml` (unaccented, lowercase) — never hardcode words or anything from a real CV in code.** Parser version = `version` + hash of that file. Matching uses `rulebook.norm`/`contains_any` (whole-word, accent-insensitive).
- **State is in-process**, so the app must run as a single instance. `core/pipeline.py` holds a process-wide `BoundedSemaphore` (`RENDER_MAX_CONCURRENT`, default 2) shared by all sessions; extra users see a "đang xếp hàng" queue (load testing showed unbounded Chromium launches exhaust RAM). Extraction has its own semaphore (`_extract_slots`, `EXTRACT_MAX_CONCURRENT`, default 2) so future OCR can't exhaust RAM; `read_cv(on_wait=...)` reports the queue position. Portrait extraction (OpenCV face detection) runs inside that slot too. PDFs longer than `MAX_CV_PAGES` (default 20) fall back to the manual skeleton (`pdf_text.TooManyPagesError`) and the "CV gốc" tab only rasterises the first pages; the preview cache (`ui/preview.py`, `PREVIEW_CACHE_ENTRIES`) is shared by all sessions.
- **PDF rendering** happens in a subprocess (`python -m services.pdf.render_worker <jobs.json> <run_id>`) because Playwright's sync API conflicts with Streamlit's event loop. `build_pdf` renders all three font-size variants (`render.FONT_SIZE_ATTEMPTS`) in one Chromium launch, then `pick_font_size()` picks one. Output must stay pixel-identical to the SKILL.md template — when touching render/template/tokens, compare page images before/after on `tests/fixtures/fake_candidate.json` (reference images: `data/baseline/`, not tracked).
- **PII protection**: the old first layer (the OpenAI prompt) is gone. Remaining: `scan_pii_export()` scans the edited JSON plus project/position; `scan_pdf()` re-scans the rendered PDF text (`pdf_clean()` gates download). `checks.py` only detects phone/email/links/social/full birth dates; addresses, hometown, marital status, nationality, ID numbers and salary are removed by the rule parser by label (`personal.py`, `[labels]` in the rules file) — `checks.py` does not yet gate them (plan step 3). Company contact info is whitelisted from `config/company.toml` (`[company]`: `name`, `address`, `phone`, `email`, `website`, `domain`; `[pdf]`: `footer_intro`, `reference_note`), the same source the template header uses — never hardcode it.
- **PDF template**: `template.html` is Jinja (one macro per section type, dispatched via the `SECTIONS` dict; `references` takes `ref_note` as an argument) and has no Jinja inside its style block: `render.pdf_css()` builds the whole stylesheet in Python (`@page` margins from `PDF_MARGIN_MM`, `css_vars("pdf")`, body font/size/line-height, then plain `template.css`) and the template only emits `{{ css }}`. The template still controls `body.compact` and `--stats-cols`. `.vscode/settings.json` maps `services/pdf/*.html` to `jinja-html` so the editor stops CSS-validating it.
- **Names that must stay in sync across files** (renaming one side breaks the other silently): `template.html` variables (`css`, `compact`, `company_info.*`, `ref_note`…) ↔ `render.render_html()` kwargs; the `{name}` placeholder in `footer_intro` ↔ `render_worker.footer_html()`; checklist dicts `{code, item, ok, detail}` and PII dicts `{field, kind, value}`; session keys in `app.py` (`review`, `stage_labels`, …) ↔ `ui/profile_form.py`.
- **Single sources of truth**: `prompts/schema.json` (the only file left in `prompts/`) ↔ `services/ai/models.py`; `infra/tokens.py` ↔ `.streamlit/config.toml` colors ↔ `ui/styles.css` (no raw hex/px font sizes/radii/spacing) ↔ the generated table in `docs/design-system.md`; PDF margins come from `PDF_MARGIN_MM`; `MAX_UPLOAD_MB` ↔ `server.maxUploadSize`. PDF metadata `keywords` = `FillCV-LightHuman; extractor <name>-<version>` (`base.extractor_version()`).
- **Logging**: `data/logs/app.log` and `render_worker.log`, each line tagged `[run_id]` (generated per uploaded CV, passed to the worker via argv; set via `set_run_id` at the top of every Streamlit rerun and inside download callbacks). `read_cv` logs one line per extractor stage (key, seconds, status, code-written detail). Never log CV content or file names — use `mask_filename()` (`pdf#<sha8>`).
- `app.py` must stay under 250 lines and free of business logic/CSS (`tests/test_structure.py` enforces it); `edit_profile` ≤ 15 lines; public functions need type hints + docstrings.

## Constraints

- Keep `server.address = "localhost"` in `.streamlit/config.toml` (no app-level auth; expose only behind an authenticating proxy / Cloudflare Access). `maxUploadSize` must equal `MAX_UPLOAD_MB`.
- Pin `opencv-python-headless<5` — 5.x removed the Haar cascade used to crop portraits.
- Use only synthetic candidate data in tests/fixtures/commits; a real CV fixture was previously purged from git history. Never copy real CVs into the repo or print their content in logs/docs. `data/` (exported PDFs, baselines, logs) is gitignored.
- Cloudflare Workers/Pages cannot host this app (long-running Python + Chromium); deployment options are a VPS/Docker or a local machine behind Cloudflare Tunnel (see README and `docs/proposals.md`).
